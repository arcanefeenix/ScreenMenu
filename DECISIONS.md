# DECISIONS

| ID | Date | Decision | Reason | Requirements |
|---|---|---|---|---|
| D-1 | 2026-10-07 | Architecture: four projects (Core, Persistence, Rendering, App) plus test projects; light MVVM with a hand-rolled `ObservableObject` / `RelayCommand`, no MVVM framework. Reliability additions beyond the spec, approved with the plan: single-instance mutex, global exception handlers, last-good frame retention, startup self-check, schema versioning with backup before migration, timestamped backups (last 10), status chip. | Keep dependencies near zero and the renderer cleanly separated. | FOUND-004, REL-002, REL-003, REL-004, RENDER-014, PERSIST-003, PERSIST-006, OPS-008 |
| D-2 | 2026-10-07 | Add a **logo** requirement (optional per menu, imported into app assets, falls back to text header). Bundle fonts and load them from a `Fonts` folder; the font is a theme setting, so a brand font can be dropped in without a rebuild. Default font is an open-licence face. | User request. Bundled fonts remove the risk of a missing system font silently changing layout and pagination, and allow branding. | MENU-007, MENU-008, RENDER-013 |
| D-3 | 2026-10-07 | **Overflow uses pagination, not scrolling and not shrinking.** Content is split into pages that rotate on a per-menu timer (default 10 s). Header/logo repeat on each page; category headers are never orphaned at the bottom; pages recompute when items are hidden or sold out. Warnings remain only for content that cannot fit even on its own page. Page indicator on the output can be turned off. | User chose pagination over scrolling. Replaces the earlier "alert the operator" proposal for ordinary overflow. | RENDER-010, RENDER-011, RENDER-012 |
| D-4 | 2026-10-07 | The app makes **no assumption about the VP2 crop anchor** (center vs top-left). Calibration includes markers at the output canvas corners and center so both cases are visible. Output size is taken from the actual display; 1920×1080 is only a test default. | User reports the VP2 crops with scaling off and the anchor is unknown; Gates 1 and 2 resolve it. | CAL-004, OUT-002 |
| D-5 | 2026-10-07 | Target **.NET 8 LTS** (SDK 8.0.425 installed, pinned by `global.json`). Distribution is a **self-contained folder with no installer**, run from the desktop. App always starts live (not in blackout). | User approved .NET 8 install; wants a run-anywhere folder; blackout on start not wanted. | FOUND-001, FOUND-006, PKG-001, OPS-006 |
| D-6 | 2026-10-07 | Shortcuts: Blackout `Ctrl+Shift+B`, Identify Screens `Ctrl+Shift+I`, Stop Output `Ctrl+Shift+F12` (not Ctrl+Shift+Esc, which Windows reserves for Task Manager). | User approved. | OPS-002, OPS-004, OPS-005 |
| D-7 | 2026-10-07 | Declare **PerMonitorV2** DPI awareness in the app manifest. | Output placement must be computed in physical pixels; the operator may use 125%/150% scaling. | RENDER-003 |
| D-8 | 2026-10-07 | The data folder is `%APPDATA%\LedMenu` (roaming AppData), with `logs`, `backups` and `assets` subfolders. Corrupt files are renamed `*.corrupt-<timestamp>` and never deleted. | Writable without admin rights; matches spec sections 19 and 22. | PERSIST-001, PERSIST-004 |
| D-9 | 2026-10-07 | Application-level XAML resources are avoided; window resources are declared in the window that uses them. | With the .NET 8 SDK the generated `Main` did not call `InitializeComponent` for the application, so app-level resources were not found at runtime. Window-level resources work reliably. | UI-001 |
| D-10 | 2026-10-07 | The **Operator display** selection is stored and shown (tag, conflict warnings) but the operator window is **not moved** to it. The app separately reports which display the operator window is actually on. | Moving windows automatically can surprise the operator; the selection exists mainly so the app can refuse to put LED output on it. Can be promoted later if wanted. | DISP-002, DISP-007 |
| D-11 | 2026-10-07 | Display identity is the monitor interface path (from the Windows display-configuration API); Windows names/numbers (`\.\DISPLAYn`) and desktop position are never used as the key. If the path is not found, a single display with identical name, resolution and position is offered as "unconfirmed" and needs operator confirmation before it counts. Anything else is "not found" and no other display is substituted. Remembered geometry is refreshed whenever the same path is seen with a different size/position. | Windows renumbers displays; two identical monitors differ only by path (confirmed on the dev PC); the user requires no automatic substitution. | DISP-004, DISP-005, DISP-011 |
| D-12 | 2026-10-07 | **Identify Displays** is built in Phase 2 as a small, auto-closing, non-focus-stealing label per monitor (labels 1, 2, 3 ordered left to right, top to bottom). It is separate from **Identify Screens** (LED regions, Phase 5). | User asked for it if practical; it was small. List numbers are labels only and are never persisted. | DISP-008 |
| D-13 | 2026-10-07 | New optional settings fields (`OperatorDisplay`, `OutputDisplay`) were added without bumping `SchemaVersion`; files from Phase 1 still load (unit-tested). | Additive and backward compatible. | PERSIST-006 |
