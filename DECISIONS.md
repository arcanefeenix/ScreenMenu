# DECISIONS

| ID | Date | Decision | Reason | Requirements |
|---|---|---|---|---|
| D-1 | 2026-10-07 | Architecture: four projects (Core, Persistence, Rendering, App) plus test projects; light MVVM with a hand-rolled `ObservableObject` / `RelayCommand`, no MVVM framework. Reliability additions beyond the spec, approved with the plan: single-instance mutex, global exception handlers, last-good frame retention, startup self-check, schema versioning with backup before migration, timestamped backups (last 10), status chip. | Keep dependencies near zero and the renderer cleanly separated. | FOUND-004, REL-002, REL-003, REL-004, RENDER-014, PERSIST-003, PERSIST-006, OPS-008 |
| D-2 | 2026-10-07 | Add a **logo** requirement (optional per menu, imported into app assets, falls back to text header). Bundle fonts and load them from a `Fonts` folder; the font is a theme setting, so a brand font can be dropped in without a rebuild. Default font is an open-licence face. | User request. Bundled fonts remove the risk of a missing system font silently changing layout and pagination, and allow branding. | MENU-007, MENU-008, RENDER-013 |
| D-3 | 2026-10-07 | **Overflow uses pagination, not scrolling and not shrinking.** Content is split into pages that rotate on a per-menu timer (default 10 s). Header/logo repeat on each page; category headers are never orphaned at the bottom; pages recompute when items are hidden or sold out. Warnings remain only for content that cannot fit even on its own page. Page indicator on the output can be turned off. | User chose pagination over scrolling. Replaces the earlier "alert the operator" proposal for ordinary overflow. | RENDER-010, RENDER-011, RENDER-012 |
| D-4 | 2026-10-07 | The app makes **no assumption about the VP2 crop anchor** (center vs top-left). Calibration includes markers at the output canvas corners and center so both cases are visible. Output size is taken from the actual display; 1920×1080 is only a test default. | User reports the VP2 crops with scaling off and the anchor is unknown; Gates 1 and 2 resolve it. | CAL-004, OUT-002 |
| D-5 | 2026-10-07 | Target **.NET 8 LTS** (SDK 8.0.425 installed, pinned by `global.json`). Distribution is a **self-contained folder with no installer**, run from the desktop. App always starts live (not in blackout). | User approved .NET 8 install; wants a run-anywhere folder; blackout on start not wanted. | FOUND-001, FOUND-006, PKG-001, OPS-006 |
| D-6 | 2026-10-07 | Shortcuts: Blackout `Ctrl+Shift+B`, Identify Screens `Ctrl+Shift+I`, Stop Output `Ctrl+Shift+F12` (not Ctrl+Shift+Esc, which Windows reserves for Task Manager). | User approved. | OPS-002, OPS-004, OPS-005 |
| D-7 | 2026-10-07 | Declare **PerMonitorV2** DPI awareness in the app manifest. | Output placement must be computed in physical pixels; the operator may use 125%/150% scaling. | RENDER-003 |
| D-8 | 2026-10-07 | The data folder is `%APPDATA%\LedMenu` (roaming AppData), with `logs`, `backups` and `assets` subfolders. Corrupt files are renamed `*.corrupt-<timestamp>` and never deleted. | Writable without admin rights; matches spec sections 19 and 22. | PERSIST-001, PERSIST-004 |
| D-9 | 2026-10-07 | Application-level XAML resources are avoided; window resources are declared in the window that uses them. | With the .NET 8 SDK the generated `Main` did not call `InitializeComponent` for the application, so app-level resources were not found at runtime. Window-level resources work reliably. | UI-001 |
| D-10 | 2026-10-07 | The **Operator display** selection is stored and shown (tag, conflict warnings) but the operator window is **not moved** to it. The app separately reports which display the operator window is actually on. | Moving windows automatically can surprise the operator; the selection exists mainly so the app can refuse to put LED output on it. Can be promoted later if wanted. | DISP-002, DISP-007 |
| D-11 | 2026-10-07 | Display identity is the monitor interface path (from the Windows display-configuration API); Windows names/numbers (`\.\DISPLAYn`) and desktop position are never used as the key. If the path is not found, a single display with identical name, resolution and position is offered as "unconfirmed" and needs operator confirmation before it counts. Anything else is "not found" and no other display is substituted. Remembered geometry is refreshed whenever the same path is seen with a different size/position. | Windows renumbers displays; two identical monitors differ only by path (confirmed on the dev PC); the user requires no automatic substitution. | DISP-004, DISP-005, DISP-011 |
| D-12 | 2026-10-07 | **Identify Displays** is built in Phase 2 as a small, auto-closing, non-focus-stealing label per monitor (labels 1, 2, 3 ordered left to right, top to bottom). It is separate from **Identify Screens** (LED regions, Phase 5). | User asked for it if practical; it was small. List numbers are labels only and are never persisted. | DISP-008 |
| D-13 | 2026-10-07 | New optional settings fields (`OperatorDisplay`, `OutputDisplay`) were added without bumping `SchemaVersion`; files from Phase 1 still load (unit-tested). | Additive and backward compatible. | PERSIST-006 |
| D-14 | 2026-10-07 | **Output safety rules.** (a) Output starts only on a display matched by device ID and connected at that moment; a fresh scan is done at every Start, and a missing, unconfirmed or unselected display refuses with a message. (b) The output window is shown without activation and is never given focus by the app. (c) **Esc** closes output only if the output window has keyboard focus, which only happens if the operator deliberately clicks it; it does nothing from the operator window. (d) **Ctrl+Shift+F12** is registered as a system-wide hotkey only while output runs (so it works even when output covers the operator window); the same shortcut is also bound in the operator window, and Stop Output is a button. (e) At start, warn again (default No) if the operator window or the only display is the target; the "primary" and "operator display" warnings are shown at selection time only. (f) If the display disappears while output runs, output stops and is not moved; if its size changes it is repositioned. (g) Closing the operator window shuts the app down. | User requirements for Phase 3; the operator must never be stranded behind a fullscreen window. | OUT-004, OUT-007, OUT-008, OUT-010, OUT-011, OUT-012, OPS-005, OPS-007 |
| D-15 | 2026-10-07 | **Pixel placement.** The output window is positioned and sized in physical pixels with `SetWindowPos` (re-applied after DPI-change messages), never through WPF's DIP Left/Top/Width/Height. Bitmaps are shown with their own DPI set to the window's DPI so one bitmap pixel is one screen pixel, using nearest-neighbor scaling. Rounded corners and the DWM border are disabled. | Makes the result independent of the operator monitor's scaling and of the output monitor's scaling. | RENDER-003, RENDER-004, OUT-001, OUT-009 |
| D-16 | 2026-10-07 | Added a **diagnostic command line**: `LedMenu.App.exe --selftest-output <report.txt>` starts and stops output twice on the saved LED display, paints a known pixel pattern, captures the real screen with GDI and compares every pixel, and checks the settings file is unchanged. It writes only the report. Screen capture uses plain GDI calls so no extra package is needed. | Gives repeatable evidence for pixel mapping and is reusable at an event or on the real VP2. | OUT-001, OUT-003, RENDER-003 |
| D-17 | 2026-10-07 | **Screen validation rules.** Width and height must be greater than zero and X and Y must not be negative (errors). A screen extending past the output canvas is an error when enabled and a warning when disabled; it is never clipped or resized. Overlap between two enabled screens is a warning only. Disabled screens are ignored for overlap and rendering. Empty or duplicate names are warnings. Validation only reports; it never edits a screen. If the canvas size is unknown, bounds are not checked. | User requirements for Phase 4. | SCR-006, SCR-007, SCR-012, SCR-013 |
| D-18 | 2026-10-07 | **Canvas for validation:** the live size of the confirmed output display; if that display is missing or unconfirmed, its last known size; if none was ever selected, unknown (the editor draws a 1920x1080 stand-in and says so). | Screens must stay flagged correctly even when the LED display is unplugged, and a changed resolution must flag, not rewrite. | SCR-014 |
| D-19 | 2026-10-07 | Screens are stored in **`screens.json`**, separate from `settings.json`. The file validator checks structure only (schema version, unique ids); it deliberately accepts out-of-range and even negative or zero geometry so user data is never rejected or lost. | Keeps screen configuration independent of the selected display and of menus; invalid definitions must be preserved. | SCR-010, SCR-012, SCR-015 |
| D-20 | 2026-10-07 | **Editor behavior.** Numeric boxes commit on Enter or when focus leaves, and each commit is saved immediately (no debounce needed); a typed value that is not a whole number is rejected by the box (red border) and the saved value is unchanged. Dragging works in whole canvas pixels, snaps to the canvas edges and to other enabled screens within 6 view pixels (Alt disables snapping), is clamped to the canvas when its size is known, and is saved once when the mouse is released. Removing a screen asks first. | Reliable numeric configuration first; drag is a convenience that resolves to integers. | SCR-003, SCR-005, SCR-017 |
| D-21 | 2026-10-07 | "Visual output placement" in Phase 4 means the **editor picture only**. Nothing is drawn on the LED output for screens yet; Phase 5 (calibration) and Phase 7 (menus) will draw them using `ScreenValidator.RenderableScreens`. | The output stays pure black until there is something deliberate to show, and no menu rendering was requested. | SCR-013, OUT-003 |
| D-22 | 2026-10-07 | `AssignedMenuId` is stored on each screen and shown as "No menu assigned" / "Menu xxxxxxxx..." but cannot be edited yet. | Preserved for Phase 6 and 8 without building menus now. | SCR-001, SCR-002 |
| D-23 | 2026-10-07 | **Calibration design.** All patterns are built as plain pixel arrays in the Core project (integer drawing, a built-in 5x7 whole-pixel font, no WPF, no anti-aliasing), so they can be tested by reading pixels back and are identical wherever they are shown. Output Canvas Calibration is independent of screens and is designed to be read from a photo: coordinate labels every 100 source pixels (double size every 200), rulers with ticks every 10, nine named anchors with their coordinates, colored 4-px edge bands (red top, blue bottom, green left, yellow right), exact center lines, circles, and 1-pixel detail blocks that blur under scaling. | Gate 1 must tell true 1:1 mapping from cropping, scaling, offset, overscan and missing rows or columns without assuming any VP2 behavior. | CAL-002, CAL-004, CAL-006, CAL-013 |
| D-24 | 2026-10-07 | **Mode rules.** The output mode is held in memory only (never saved) and always starts as Normal. Stopping output resets it to Normal. Identify Screens returns to Normal after 15 seconds; the two calibration modes stay until changed. A visible magenta banner and a TEST label on the status chip show whenever a mode is selected or live. Test patterns draw only enabled screens that pass validation; invalid ones are reported, not drawn; disabled ones are left out; overlapping ones are drawn in list order. | A pattern must never reach the audience unnoticed or look valid when it is not. | CAL-008, CAL-010, CAL-011, CAL-012 |
| D-25 | 2026-10-07 | Two diagnostic command-line modes: `--dump-calibration <folder> [WxH]` and the existing `--selftest-output`, which now also compares every mode with a capture of the real screen. | Repeatable evidence and offline reference images for reading photos. | CAL-015 |
| D-26 | 2026-10-07 | Numeric fields: an invalid entry may show while being edited, but when focus leaves the box it reverts to the value actually stored. | User request after Phase 4 review. | SCR-003 |
| D-27 | 2026-10-07 | **VP2 behavior (Gate 1 result, user-verified).** With the Windows output at 1920x1080 and VP2 scaling disabled, the Mirackle VP2 is **top-left anchored** and maps source pixel (0,0) to the physical top-left LED at exactly 1:1. The current 7x2 wall (1176x672) shows the upper-left 1176x672 region of the 1920x1080 source, with no scaling, offset, or visible overscan. A 336x672 Screen at X=0, Y=0 occupies exactly the leftmost 2x2 panel region (168x336 per panel), with the remainder of the wall unused. Anything at source X >= 1176 or Y >= 672 is off the wall. The app still assumes none of this: screen positions remain user-entered numbers and the calibration tools remain available. | Result of Gate 1, reported by the user. | CAL-004, CAL-005, OUT-002 |
